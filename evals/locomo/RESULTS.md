## Methods

- `bm25`: BM25 only
- `recency`: most recent first (no query)
- `bm25+recency`: BM25 x fixed recency blend (half-life 30d, floor 0.5)
- `embedding`: MiniLM cosine only
- `bm25+embedding`: hybrid relevance (0.5 BM25 + 0.5 cosine), nothing else
- `heapdb`: HeapDB memory, no learning: relevance x recency x importance x prior usefulness
- `heapdb+learned`: HeapDB memory with usefulness learned on the other 9 conversations
- `heapdb+learned+tuned`: as heapdb+learned, with recency/importance weights and half-life chosen per fold on the 9 training conversations (nested CV)
- `bm25+embedding+tuned`: hybrid relevance only, BM25 share chosen per fold on the training conversations (nested CV); fair baseline for the tuned HeapDB rows
- `heapdb+emb`: HeapDB memory, hybrid relevance, no learning
- `heapdb+emb+learned`: HeapDB memory, hybrid relevance, learned usefulness
- `heapdb+emb+learned+tuned`: as heapdb+emb+learned, weights and BM25 share tuned per fold on the training conversations
- `abl:-recency`: -recency
- `abl:-importance`: -importance
- `abl:-usefulness`: -usefulness
- `abl:bm25+importance`: bm25+importance
- `abl:bm25+learned`: bm25+learned

## Setup

- Dataset: `locomo10.json`, sha256 `79fa87e90f04081343b8c8debecb80a9a6842b76a7aa537dc9fdf651ea698ff4`, downloaded at run time (CC BY-NC 4.0, not redistributed).
- Excluded: 4 questions without evidence (category 3); 0 whose evidence ids do not exist; 2 kept with an unresolvable evidence id dropped. Malformed ids like `D8:6; D9:17` and `D:11:26` are parsed.
- Memory = `"<speaker>: <text>"` plus `[shares <caption>]` for image turns; kind `episode`, source = speaker, created at session time + 1 min per turn. Query time = 1 day after the last session.
- Ranking depth 50; training feedback: recall top 10 per training question, `mark_used` the evidence turns among them, `mark_ignored` the rest.
- Embeddings: sentence-transformers all-MiniLM-L6-v2, ONNX export, sha256 `6fd5d72fe4589f189f8ebc006442dbb529bb7ce38f8082112682524616046452`, run with `OnnxEmbedder` (mean pooling, L2 norm).
- Runtime 4655.4 s.

The model learns *which kinds of memory are useful for which kinds of question*: a turn with a date for a *when* question (`qt:when&date:yes`), a number for *how many* (`qt:howmany&num:yes`), a turn by the person the question names (`qsrc:yes` vs `qsrc:no`), and not turns that are themselves questions (`q:yes`). These patterns carry over to a conversation the model has never seen, and that is where the held-out gain comes from. The held-out namespace gets no feedback at all: it borrows the pooled global links through HeapDB's hierarchical prior. The per-memory links (`mem:<id>`) cannot contribute on held-out data (those memories never got feedback). They only matter in real use, where the same memories are recalled repeatedly.

### Where HeapDB does not help (or hurts)

- **Recency.** LoCoMo questions ask about any point in a 6-10 month history, all at one query time, and no memory is re-used before the test query. So time since last use carries no signal here. The default `w_recency=1` (half-life 30 d, floor 0.5) costs -0.043 MRR, and `recency`-only scores 0.005. Nested-CV tuning picked `w_recency=0` in 18 of 20 fold choices (else [0.25]). Recency should matter for temporally local agent queries ("what did we decide yesterday") and with `mark_used` reinforcement. This benchmark cannot show that, and we do not claim it. For archive-style recall over long histories, set `w_recency=0`.
- **Untuned defaults do not beat plain BM25.** `heapdb` scores 0.421 vs 0.459 for BM25 (recency alone explains the gap). `heapdb+learned` with defaults: ΔMRR -0.005 [-0.014, +0.004]. The gains need learning *and* a recency weight that fits the workload.
- **Hybrid relevance with a fixed 50/50 mix** ties BM25 (ΔMRR +0.005 [-0.005, +0.014]). The default `heapdb+emb` rows are worse than the lexical ones. Tuning chose BM25 share [0.7] in every fold.
- **Embedding-only retrieval** (all-MiniLM-L6-v2, MRR 0.263) is far below BM25: LoCoMo questions reuse the names and nouns of their evidence, and MiniLM-L6 is small. A stronger embedder would likely narrow the gap; we did not test one.
- **Open-domain questions** (inference or world knowledge) gain little (+0.010 from learning). Evidence that shares neither words nor features with the question stays hard to find.
- **Absolute numbers are modest.** The best row (`heapdb+emb+learned+tuned`) puts 60.5% of evidence turns in the top 5 (R@5). The lift from learning is real but small (a few hundredths of MRR), in line with earlier HeapDB benchmarks where timing and dose mattered more than learning.

### Threats to validity

- Training feedback is *oracle* feedback: the evidence turns among the top 10 are marked used, and the rest ignored. Real agent feedback (what it actually cited) will be noisier and sparser.
- Category names are read off the questions (the file has only codes 1-5). The mapping is the one commonly used for LoCoMo.
- The tuning grids (`TUNE_GRID`, `TUNE_LEXICAL` in `run.py`) are small and were fixed in advance. Only training-fold MRR picks from them.
- Latency is single-threaded Python on a shared VM: an order of magnitude, not a benchmark.
